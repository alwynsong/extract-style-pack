# 色卡与验收

本文件定义联系表、双版色卡、颜色同步和最终验收。

## 1. 联系表

必须生成：

- `参考素材/总览-contact-sheet.jpg`：全部正式分析画面；
- `参考素材/视频抽帧总览/VID-0001.jpg`：每个视频的保留帧；
- `参考素材/分组总览/NN-[分组名].jpg`：每个视觉分组。

超出单页容量时使用 `-01`、`-02` 分页。联系表必须保留可读文件名或 ID。

`render_style_pack.py --mode review` 只生成视频审核拼图；`--mode final` 生成所有正式联系表与色卡，并写 `分析/联系表生成记录.json`。

## 2. 色卡数据

每个正式分组固定 10 色：

- 3 个主色：P1–P3
- 5 个辅助色：S1–S5
- 2 个点缀色：A1–A2

取色只使用分组中的正式画面，不使用联系表、已有色卡、过滤素材、Logo 或字幕。先裁掉明显黑边或白边，再适度降采样和聚类，避免边框占据主色。

`分析/色卡数据.json` 是颜色事实文件，至少记录 `project`、`card_size: [1920, 1080]`、`color_model: "3 主色 + 5 辅助色 + 2 点缀色"`，以及每组名称、来源画面、10 个色位的 HEX/RGB、角色说明和生成文件路径。

每组生成：

```text
参考素材/分组/01-[分组名]/00-[分组名]-色卡.png
参考素材/分组/01-[分组名]/00-[分组名]-纯色色卡.png
```

同时生成 `参考素材/分组色卡总览.jpg` 与 `参考素材/纯色色卡总览.jpg`。

## 3. 两种色卡

标注色卡用于阅读，应显示项目、分组、色位、HEX 和颜色角色。

纯色色卡用于机器取色：

- 必须是 1920×1080 RGB PNG；
- 恰好 10 个色块；
- 每种颜色精确占相同像素数；
- 不含文字、边框、阴影、透明度或抗锯齿混色。

## 4. 人工色彩复核

脚本聚类后，Agent 查看分组原图、标注色卡和纯色色卡总览，检查：

- 主色是否真正在组内占主导；
- 辅助色是否覆盖稳定环境与材质色；
- 点缀色是否稀有但有视觉作用；
- 黑边、字幕、肤色或单一物体是否被错误放大；
- 各组是否因为算法而趋同；
- 标注与实际 RGB/HEX 是否一致。

需要调整时，以视觉证据修改 `色卡数据.json`，再重新渲染；脚本默认复用已有 JSON。只有分组或素材改变后才使用 `--recompute-palette` 重新取色。之后再写 `design.md`、风格规则和分组提示词中的 HEX。

## 5. 自动校验

运行：

```bash
python -X utf8 scripts/validate_style_pack.py \
  "<风格包目录>" \
  --visual-review-confirmed
```

校验器独立检查根文档、manifest、媒体报告、逐图标签、素材数量、路径、视频索引、分组成员、同名提示词、双版色卡、文档 HEX、联系表记录和隐私信息。退出码非 0 表示未通过，修复后必须重跑。

## 6. 最终人工验收

自动校验不能替代视觉检查。交付前确认：

- 所有拼图能打开，缩略图未错误旋转或拉伸；
- 每个正式画面都有逐图观察；
- 分组确实按视觉特征，而非按时间或剧情；
- 每组至少两张有效画面且组内一致；
- 色卡与真实画面相符；
- 提示词能在不引用原作专名时保持风格；
- `00-说明.md` 写明来源范围、素材缺口、人工调整和不确定性。

只有自动校验无错误且上述检查完成，才可记录 `--visual-review-confirmed` 并交付。
