# 视觉分析与分组

本文件定义 Agent 承担的视觉判断。核心顺序是：逐图观察 → 建立分组 → 总结规律 → 写提示词。

## 1. 正式分析集合

只分析：

- `参考素材/标准化图片/`
- `参考素材/视频抽帧/*/保留帧/`

不分析原始文件、过滤素材、联系表、色卡或其他派生图。每张正式画面都必须在 `分析/单图标签-第一版.json` 出现一次。

## 2. 逐图标签

顶层结构：

```json
{
  "schema_version": "1.0",
  "items": []
}
```

每项至少包含：

```json
{
  "asset_id": "IMG-0001",
  "file": "参考素材/标准化图片/IMG-0001.jpg",
  "source_type": "image",
  "space": "空间与环境观察",
  "shot_and_subject_ratio": "景别、视角和主体占比",
  "composition": "构图、层次和视觉动线",
  "lighting": "主光方向、软硬、反差和实景光源",
  "color": "主导色、冷暖关系和饱和度",
  "camera_and_texture": "焦段感、景深、运动与成像质感",
  "material": "表面、服装、道具和环境材质",
  "mood": "情绪与节奏",
  "image_specific_evidence": ["本图独有证据 1", "本图独有证据 2"],
  "transferable_features": ["可迁移特征"],
  "avoid_identifiable_elements": "需要去除的角色、肖像、Logo、文字或原作专属符号",
  "visual_group": "01-分组名"
}
```

要求：

- 描述画面中真实可见的内容，不把推测当事实；
- `composition` 与 `shot_and_subject_ratio` 不得互相复制；
- 每图至少两条专属证据，不得整段复制同组模板；
- `visual_group` 可在分组确定后回填；
- 视频帧的 `asset_id` 使用帧 ID，`source_type` 使用 `video_frame`。

## 3. 分组逻辑

分组按可迁移视觉特征，不按故事幕、时间段、角色或具体地点。两个相距很远的场景，只要在空间、光线、色彩、材质和构图上形成同一稳定模式，就可以归为同一组。

优先考虑空间类型与尺度、色温/对比/饱和度、主光方向与光比、构图密度与主体比例、焦段感与景深、材质组合、氛围和视觉节奏。

每组至少 2 个真实画面。一个画面可被复制到多个有充分证据的分组，但应有一个主要用途。组名采用 `NN-[视觉模块]`，例如 `01-靛青密闭空间`，不要使用剧情命名。

不要先决定固定组数。通常 3–8 组足够；视觉差异不足时宁可少组。

## 4. 分组总结

`分析/分组总结.md` 对每组至少写：

- 该组解决什么类型的画面；
- 成员文件与关键证据；
- 稳定共性；
- 允许变化的部分；
- 与相邻分组的区别；
- 适用场景与易跑偏点。

所有结论必须能从本组画面或逐图标签中找到证据。不要把单一画面的偶然元素写成全局规则。

## 5. 风格规则

`design.md` 与 `分析/风格规则-第一版.md` 应覆盖总体视觉 DNA、构图与景别、色彩、光线、镜头与成像质感、材质、场景与造型规律、禁止元素、常见偏差和各分组边界。

文档中的 HEX 必须来自最终 `分析/色卡数据.json`，不要在色卡确定前凭估计写入颜色值。

## 6. 分组提示词

每个 `分析/分组提示词/NN-[分组名].md` 使用相同骨架：

- 这个分组解决什么画面
- 视觉锁
- 可替换变量
- 提示词：风格环境、主体与调度、构图景别、摄影参数、光线色调、材质细节、氛围情绪、画面限制
- 视频提示词
- 适合生成的镜头
- 容易跑偏的地方
- 自检清单

提示词先锁定可迁移视觉机制，再开放主体、地点和动作变量。避免使用演员姓名、受保护角色、片名、Logo、原作独有服装或道具来替代视觉描述。
