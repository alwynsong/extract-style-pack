# 输入与输出契约

本文件定义所有任务都必须遵守的来源、目录、命名和可移植性约束。网络视频细节见《网络视频与抽帧》。

## 1. 输入与来源

可接收用户上传文件、本地路径、公开网页图片、直接媒体 URL 和公开网页中的视频。用户未提供素材时，Agent 可搜索并选择能代表目标视觉的公开来源。

优先级：

1. 用户明确指定的文件或 URL；
2. 官方发布或权利方公开素材；
3. 可追溯的高质量媒体来源；
4. 仅作补充的搜索缩略图。

不得伪造来源，不得绕过 DRM、登录、付费墙、验证码或访问限制。记录原始页面 URL，不把临时签名链接、Cookie 或凭据写入交付物。

## 2. 最小素材要求

正式分析画面默认至少 8 张，并尽量覆盖不同空间、尺度、光线和色彩倾向。素材不足时不要用重复帧凑数；继续补充来源，或在 `00-说明.md` 明确局限。

图片和视频先保存到：

```text
参考素材/原始文件/图片/
参考素材/原始文件/视频/
```

原始文件不修改。正式分析只使用 `参考素材/标准化图片/` 与各视频的 `保留帧/`。

## 4. ID、命名与路径

- 图片素材：`IMG-0001`
- 视频素材：`VID-0001`
- 视频帧：`FRM-VID-0001-0001`
- 视觉分组：`NN-[简洁中文分组名]`

ID 在项目内唯一且不复用。分组名称描述可迁移视觉模块，不使用角色、地点或剧情事件命名。

JSON 和 Markdown 内部路径必须：

- 相对风格包根目录；
- 使用 POSIX `/`；
- 不含盘符、用户名、主目录、`..` 或临时目录。

## 5. manifest

`参考素材/manifest.json` 是来源事实文件。最低结构：

```json
{
  "schema_version": "1.0",
  "project": "项目名",
  "created_at": "ISO-8601",
  "sources": [
    {
      "asset_id": "IMG-0001",
      "media_type": "image",
      "source_type": "uploaded_file",
      "page_url": null,
      "local_path": "参考素材/原始文件/图片/IMG-0001.jpg",
      "status": "processed",
      "included_in_analysis": true,
      "sha256": "64位十六进制"
    }
  ]
}
```

`source_type` 使用 `web_search`、`local_file`、`uploaded_file`、`media_url` 或 `web_page`。`status` 使用 `discovered`、`downloaded`、`copied`、`inspected`、`processed`、`filtered`、`duplicate` 或 `failed`。失败项保留记录并填写 `failure_reason`。

视频完成后还要填写 `frame_index`、`kept_frame_count`，并标记 `processed` 与 `included_in_analysis: true`。

## 6. 覆盖和增量

目标已存在但用户未要求更新时，不静默覆盖；创建新版本目录或在选择会影响结果时确认。明确要求更新时保留旧 ID，新素材使用新 ID，只重跑受影响的准备、分组、渲染和校验步骤。

## 7. 隐私与交付

交付物不得包含 API Key、Cookie、令牌、密码、私人邮箱、用户主目录绝对路径、临时签名参数或不必要的 EXIF 定位信息。未经用户明确要求，不上传私有素材。
