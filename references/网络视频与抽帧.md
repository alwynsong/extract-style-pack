# 网络视频与抽帧

本文件处理 YouTube、哔哩哔哩等公开网络视频，以及本地视频的通用抽帧。下载与抽帧分离：Agent 负责取得本地文件，`extract_video_frames.py` 负责环境预检和本地视频抽帧，因此可被其他 Skill 复用。

## 1. 强制依赖预检

网络视频任务必须先运行：

```bash
python -X utf8 scripts/extract_video_frames.py --check
```

完整网络视频流程要求 `yt-dlp`、FFmpeg 与 FFprobe 均可用；本地视频抽帧只要求 FFmpeg 与 FFprobe。依赖解析顺序固定为：

1. PATH 中的命令；
2. 用户提供的绝对路径；
3. `python -m yt_dlp`；
4. macOS 与 Windows 的常见包管理器安装目录；
5. 当前平台可用的官方安装方式或包管理器。

缺失依赖时不要只报告错误。Agent 应先定位已有安装；仍缺失时，按当前环境的网络、写入和管理员权限规则主动发起安装。安装不得静默进行，也不得在 `extract_video_frames.py` 内修改系统环境。

安装与重试上限：

- 每个缺失依赖最多发起一次安装；
- 安装后最多复检一次；
- yt-dlp 因站点解析器过旧失败时，最多升级并重试一次；
- 仍失败则停止视频获取，记录唯一阻塞项，并改用其他公开来源或请用户提供本地视频。

yt-dlp 是 Python 核心依赖，正常通过 `requirements.txt` 安装。FFmpeg/FFprobe 必须使用系统可执行程序，不要安装同名 Python 包替代。YouTube 报告 JavaScript runtime 或 EJS 缺失时，再按 yt-dlp 官方说明安装兼容运行时；不要为此反复更换下载参数。

## 2. 选择视频

优先官方预告片、官方片段、官方 MV、公开幕后或权利方发布内容。选择能覆盖目标视觉的最少视频，不要因多个镜像版本重复下载。

记录视频页面 URL、标题、发布者、选择理由、获取日期、时长、本地路径、版权或使用限制，以及失败原因（如有）。

## 3. 获取本地文件

预检通过后优先使用 `yt-dlp`；直接媒体 URL 可用常规 HTTP 下载。不要为特定网站新增下载脚本。

示例：

```bash
python -m yt_dlp --no-playlist \
  -f "bv*[height<=1080]+ba/b[height<=1080]" \
  --merge-output-format mp4 \
  -o "<原始视频目录>/VID-0001.%(ext)s" \
  "<公开视频页面 URL>"
```

原则：

- 下载满足分析所需的最低清晰度，通常 720p 或 1080p；
- 不下载播放列表、弹幕、评论或无关元数据；
- 不传入浏览器 Cookie，不绕过登录、地区、DRM、验证码或付费限制；
- 下载失败时先判断是来源限制还是解析器过旧；解析器过旧只允许升级并重试一次，然后换公开官方来源；仍失败则请用户提供本地文件；
- 下载完成后把最终页面 URL、本地路径、SHA-256 和状态写回 `manifest.json`。

不要读取浏览器 Cookie 来绕过站点限制。登录验证、地区限制、DRM、验证码或付费墙导致失败时，直接切换合法来源或请求本地文件，不进入参数重试循环。

## 4. 抽帧命令

`extract_video_frames.py` 输入必须是本地视频：

```bash
python -X utf8 scripts/extract_video_frames.py \
  "<视频路径>" \
  --asset-id "VID-0001" \
  --output-dir "<风格包>/参考素材/视频抽帧/VID-0001"
```

依赖：FFmpeg 与 FFprobe 可由脚本自动发现。也可用 `--ffmpeg`、`--ffprobe` 指定路径。若命令在安装后仍不可见，先重新运行 `--check`，不要重复安装。

默认策略同时使用场景变化候选、均匀候选、质量过滤、感知去重和基于时长的数量上限。不要只用固定间隔，也不要只用场景检测。

## 5. HDR 与色彩

脚本通过 FFprobe 检查色彩信息。HDR、HLG 或未知色彩传递函数必须记录在 `frames.json`。没有可靠色调映射条件时，不应把明显失真的帧直接用于最终色卡；可换 SDR 来源，或在 `00-说明.md` 说明限制。

## 6. 输出

每个视频目录必须包含：

```text
VID-0001/
├── 原始抽帧/
├── 保留帧/
├── 被过滤帧/
└── frames.json
```

`frames.json` 至少记录视频素材 ID、源文件、时长、毫秒时间单位、候选与保留数量、筛选/去重状态，以及每帧的 ID、文件名、时间戳、方法、状态、路径、尺寸和质量指标。

保留帧文件名必须包含视频 ID 与毫秒时间戳，保证排序和追溯稳定。

## 7. 人工审核

抽帧完成后运行：

```bash
python -X utf8 scripts/render_style_pack.py "<风格包>" --mode review
```

Agent 查看 `参考素材/视频抽帧总览/`，人工处理片头片尾、Logo、大面积字幕、黑场、闪白、转场混合帧、严重运动模糊、无新增视觉信息的重复帧，以及与目标风格无关的画面。

移动或删除保留帧时同步更新 `frames.json` 与 manifest 的 `kept_frame_count`。每个正式视频至少保留 3 帧；少于此数量应补抽或排除该视频。

## 8. 复用边界

其他 Skill 可先复用 `extract_video_frames.py --check` 检查完整媒体环境，再提供本地视频、稳定的 asset ID 和独立输出目录进行抽帧。调用方负责网络获取、最终人工筛选和把抽帧索引接入自己的产物结构。
